# 个人贡献与 AI 辅助说明

## 我的主要贡献

### 选题与业务方向

我提供题目与公司业务介绍材料，要求先理解业务和验收要求，再选择“内容任务规划 Agent”展开实现。我将交付重点放在预算和截止时间内形成可保存的活动方案，并以题目要求的正常完成、信息不足、预算超限、工具失败和重复执行作为验收依据。

### 范围决策与分阶段规划

在 AI 辅助分析的基础上，我确认了开发方案和分阶段实施顺序：先使用 Mock 跑通离线业务、状态和校验，再接入真实模型验证动态决策。技术路线采用 Python 原生单 Agent 循环、Pydantic、SQLite 和 CLI，优先完成可运行、可追溯的核心链路。真实视频制作、广告投放和失败任务跨进程续跑暂不纳入本次交付。

### 接入与可复用性要求

我申请并提供阿里模型 API 的本地接入条件，推动项目从离线验证进入真实模型验证。同时，我明确提出不应依赖本机 CSV 调用：改用 `.env` 和空密钥模板，使其他人可以填入自己的配置；接口也应采用通用 OpenAI 兼容形式，而不是固定为某个百炼地址。

### 使用反馈与交付取舍

检查 CLI 使用方式时，我指出单次运行和完整 JSON 输出不方便持续使用，提出增加连续对话和易读结果的要求，推动实现需求补充、修改预算、会话保存及执行进度展示。我还要求对照审查文档修复问题、清理重复测试产物，并参考交付示例将 README 的安装与快速运行前置，让评审能够更快找到入口。

上述贡献主要是业务目标、方案确认、范围取舍、接入准备和使用反馈；代码实现与技术验证的执行工作见下节。

## AI 实际承担的工作

Codex 辅助完成需求拆解、方案细化、Python 代码、合成商品与素材、费用和耗时规则、可执行测试、实际案例运行、文档撰写、Git 提交与仓库同步。具体包括：

- 实现四个业务工具、模型决策循环、输入和动作校验、模拟账本、事务保存与回读、幂等请求和证据导出。
- 实现真实 OpenAI 兼容适配器、`.env` 配置、持续对话 CLI 和结构化结果展示。
- 执行自动化测试与真实 API 案例，依据失败结果修正重试计数、估算有效性和显示方式等问题。
- 整理实际输入、输出、Trace、版本信息、API 用量及提交材料。

代码实现与命令执行主要由 Codex 完成；我负责上述方向与需求决策，暂无单独记录的本人独立编码、代码级修改或完整手工复测清单。

## 验证结果与边界

当前保留的自动化报告为 82 项测试通过；真实模型材料保留两条不同执行路径和一次零新增 API 回放。输入、实际结果和版本说明见 [评估](03-evaluation.md)，对应命令和案例由 AI 助手执行。

开发过程中另进行过持续对话真实试用，发现模型在自由说明中复述错一次截止月份，而结构化日期正确；完成摘要因此改为直接展示程序校验过的字段。详细开发期重复目录已按我的整理要求移除，题目验收记录保留。

Mock 只验证流程；有限真实案例不代表任意模型或未测输入都可靠。未验证实际账单、真实视频服务和商业效果，也未实现崩溃业务任务自动续跑。
