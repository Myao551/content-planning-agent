# 实现复盘

## 已观察到的难点

预算不能只看当前方案的标价。生成或失败后已经产生的模拟费用属于沉没支出，换方案时仍要计算；因此采用逐笔账本和与版本绑定的估算，而不是让 Mock 自报金额。

另一个问题是把所有同参数调用都限制为两次，会错误阻止“预估—生成—复核”中的合法重复估算。测试实际暴露了该问题，现已分别记录全部尝试与连续失败，只对连续失败限制重试。

保存成功也不能只依赖一条字符串。实现将方案、回执和步骤放入同一事务，并在结束前回读。数据库触发器注入失败的测试验证了没有留下成功方案或成功保存步骤。

## 本阶段收获

- 业务约束和状态应由可测试程序执行，驱动只提出动作。
- 固定 Mock 可以有效检查系统流程，但不能证明模型的动态决策能力。
- 示例必须来自实际运行，预期业务失败也可能是正确验收结果。
- 实现摘要、数据版本、固定时钟和故障配置有助于解释不同运行记录。

## 时间记录与个人边界

首次 AI 辅助实现的记录窗口为北京时间 2026-10-28 17:27:23 至 17:47:01，共 1178 秒，包含工具运行和等待，不代表全部开发时间，也不代表候选人个人工时。候选人的个人用时、最难问题与个人学习收获尚未经本人确认，不在此代填。

## 已知限制与下一步

最初先验证离线版本，随后接入真实模型；当前仍没有联网素材、视频制作、翻译、广告投放或商业效果验证。检索是小数据集关键词匹配，脚本是有来源的事实拼接，方案档位和依赖骨架有限。

随后已接通真实千问模型。正常用例曾跳过预估，被程序以 stale_estimate 拒绝后，模型根据返回自行补做估算并完成；这表明工具校验不能依赖提示词遵守。三个真实模型任务合计约 15 万 token，工具定义和多轮历史有明显上下文开销，后续可压缩冗余状态；未做优化后的真实对比实验。

后续已完成真实模型接入和三条任务路径。下一步增加资料和规则扰动、真实预算无解等案例，优化上下文开销，再考虑失败跨进程续跑、真实工具费用核对和更丰富的方案空间。

持续对话与易读输出已按试用反馈实现。真实模型可能在自由说明中复述错已知数值或日期，因此完成摘要直接从可信结构化字段展示；不能仅凭自然语言叙述判断成功。当前未做 token 流式输出或崩溃业务任务续跑。
