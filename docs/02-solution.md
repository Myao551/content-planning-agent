# 实现方案

## 架构与职责

采用 Python 3.12 原生单循环、Pydantic 2、argparse 和标准库 SQLite。模块职责为输入/动作契约、循环、离线驱动、业务工具、约束计算、持久化和证据导出。

```mermaid
flowchart LR
    H[持续对话与需求草稿] --> A[CLI 校验与重复请求检查]
    A --> B[Mock 或真实模型选择动作]
    B --> C[参数/依赖/预算/时间校验]
    C --> D[执行业务工具或返回拒绝]
    D --> E[事务保存状态、回执和费用]
    E --> B
    E --> F[结束核验与证据导出]
```

驱动通过 `ModelClient.next_action(context)` 与 `generate_script(request)` 接入。输入上下文是副本，驱动不能直接修改可信状态；实际模拟费用、产物标识与回执由程序生成。真实入口现为通用 OpenAI 兼容 Chat Completions 适配器，保留旧百炼类名的兼容入口；已有真实效果记录来自千问。

真实适配器使用标准库 HTTP 请求原生 Function Calling，每轮只接受一个工具调用；保留 native tool_call_id / assistant tool_calls，并以对应 role=tool 回传结果。厂商参数来自配置，已验证的千问案例显式关闭思考模式，默认通用请求不携带该厂商选项。公开动作说明和引用事件号由模型填写，不采集内部思维过程。真实脚本也通过 API 生成，但采用逐字事实引用约束。

请求超时取 30 秒和任务剩余实际时间的较小值，不做隐藏 HTTP 重试。自动读取当前目录 `.env` 的 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`；环境覆盖文件，命令参数再覆盖。可显式指定配置文件或沿用 CSV。允许任意 HTTPS 服务商和回环 HTTP 本地服务，不跟随重定向，不把密钥、接口地址或错误响应正文写入证据。实际 token 用量与模拟账本分开。

厂商扩展仅通过 `OPENAI_EXTRA_BODY` 显式配置，默认没有 `enable_thinking`；不再要求千问模型名前缀。接口需要支持原生工具调用与 JSON 对象输出，Responses-only 或仅兼容文本聊天的端点不在此适配器范围。

## 调用与动态分支

正常路径：检索 → 更新计划 → 估算 → 生成脚本 → 复核估算 → 保存 → 申请完成。标准方案超限后，离线策略依据估算的可行性尝试复用或简化方案。没有可复用素材时跳过复用档位。工具失败后最多尝试两次，再停止。

以上描述 Mock 的确定性策略，不能证明模型会重规划。真实适配器由模型选择动作，受到同一套程序约束；已观察的不同路径见 [真实评估](06-real-api-evaluation.md)。

计划骨架固定为素材 → 脚本 → 复核 → 保存；工具可以执行预估、重新估算和重试。计划包含档位与素材，版本变化使旧估算失效；估算还绑定账本、累计耗时、成功产物和数据版本。

检索对明确商品标识做过滤，对未指定商品的查询匹配关键词；多商品歧义或资料不足请求补充。该检索适用于小规模合成资料，没有验证真实跨语言召回效果。

## 费用与时间

| 档位 | 脚本费 | 资源预留 | 脚本模拟耗时 |
| --- | --- | --- | --- |
| standard | 4 | 8 | 180 秒 |
| reuse | 2 | 6 | 90 秒 |
| minimal | 1 | 2 | 60 秒 |

检索免费、30 秒；估算免费、0 秒；保存默认免费、1 秒。数据和价格可以通过 `--data-dir` 替换；配置校验要求检索/估算免费且估算耗时为零。

预算 10 时，先估算标准 12、再估算复用 8，生成消耗 2，保留资源预算 6。若标准脚本已产生费用 4 后又生成复用脚本，总额为 `4 + 2 + 6 = 12`，原费用不会消失。

时间游标是 `max(实际现在, 开始时间 + 已累计模拟耗时)`；预计完成时间加上剩余规划步骤耗时。实际运行另受单次任务墙钟上限约束。固定演示时钟用于测试，不把模拟耗时当成真实服务延迟。

## 事务、重复执行与故障

SQLite 五张业务表存任务、步骤尝试、工具回执、模拟费用和最终方案，另有 chat_sessions 表保存持续对话。保存方案、工具回执和步骤结果在同一事务写入；事务失败回滚，结果不能标为已保存。结束前再次回读方案。

同请求 ID 和规范化输入回放结果；不同输入返回冲突；运行中任务拒绝第二次启动。未完成任务只回放现有结果，不自动续跑。相同依赖的脚本可复用，不重复模拟扣费。

执行前故障注入不收费；显式 `after_charge` 场景保留已发生模拟费用。故障设置仅来自 CLI 演示配置，不是模型参数。失败重试按连续失败计数，正常的前后两次估算不会被误认为失败重试。

默认限制为 12 个动作、10 次业务工具、16 次驱动调用、180 秒实际运行时间、同一步最多两次连续失败。离线模式不联网；真实模式有 HTTP 请求超时。任意其他同步扩展函数阻塞时不能保证中途强制打断，返回后会检查墙钟上限。

## 输出与证据

`chat` 提供逐行持续对话。真实模型接待层基于当前草稿、目录、最近可信结果及最近 16 条对话提议结构化意图和字段修改；Pydantic 拒绝额外字段，不能修改费用或保存状态。缺信息或存在待确认问题时不执行任务，完整转录存入本地 SQLite。Mock 接待层只用简单中文规则，`/set` 在两种模式中均由本地确定性解析。

需求完整后复用原 Agent 和业务校验；修改需求产生独立请求，保留旧任务和账本，预算按任务计算。完全相同输入的 `/run` 复用最近请求 ID。会话可跨进程恢复需求、对话和任务引用，不等于崩溃任务续跑；Ctrl+C 中断时仅保留最后已提交状态并标记未完成。

对话理解/解释请求单独记入会话 usage_records，任务 Trace 和 provider_usage 只统计本任务；会话累计量包含二者，避免重复计数。`/status`、`/json`、`/set` 不请求 API。会话导出记录接待提示词摘要、创建版本和各轮结构化解释，任务元信息仍保留各自不可变执行版本。

终端自动显示中文摘要与步骤进度，重定向/管道保留 JSON，`--format` 可显式覆盖。完成摘要直接展示可信结构化字段，不重复打印模型对费用或日期的自由复述；原解释保留在 JSON。显示观察器拿到状态副本，动作结果只在事务返回后通知；显示错误不影响可信业务状态，文本过滤终端控制字符。当前没有 token 流式输出或通用代码执行工具。

结果包含任务终态、计划版本、实际步骤状态、工具结果、费用、时间、保存信息、缺失字段与保留产物。Trace 用事件序号关联动作与观察到的返回，不记录内部思维过程。

证据元信息记录 Python/Pydantic/包版本、实现源码摘要、资料摘要、限制、故障注入和时钟。离线模式提示词摘要为 null、真实请求数为 0；真实模式记录模型、提示词摘要、响应标识和供应商 token usage。历史回放本次请求数为 0，原运行用量单独保留，不重复计入新增用量。

元信息 v2 将版本分为 `execution_version` 与 `exporter_version`。前者在新任务创建时读取源码文件快照、Python/依赖版本、Git commit 和脏状态，保存到 SQLite，后续导出与回放均保留原值；后者在每次导出时采集，另记 `exported_at`。顶层 `implementation_hash` 兼容字段只指向执行摘要，不再指向当前导出器。

`git_dirty` 检查 src、data、scripts、tests、pyproject.toml 和 requirements.txt；`git_worktree_dirty` 另记全工作区状态。因此生成新的证据文件不会冒充实现发生变化。源码摘要覆盖包顶层 Python 文件，数据使用独立 catalog_hash。安装后的 wheel 只记录包源码摘要，不借用调用者当前目录的 Git commit。

历史任务没有快照时标记 `unknown_legacy`、执行摘要为 null，不反推为当前版本。v1 历史文件保持原样，其 implementation_hash 仅是当时导出时读取的源码摘要，解释见 [版本说明](../examples/provenance-notes.json)。冻结后可运行 `python scripts/evaluate_real.py --require-clean --cases normal replan repeat`；代码未提交会在读取凭据和调用 API 前被拒绝。

安装版本见 [依赖锁定](../requirements.txt)；可复现运行见 [README](../README.md)。
