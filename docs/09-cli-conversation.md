# 持续对话 CLI 与试用反馈

用户试用时指出原 CLI 只能运行一次任务，而且完整 JSON 难以阅读。本次增加 `chat` 入口，保留 `run`、`inspect`、`export` 与 JSON 自动化输出。

实现包括分轮补充需求、在原草稿上修改预算或截止时间、查询解释、SQLite 会话保存和恢复、中文任务摘要和逐步执行进度。启动方式与可直接输入的例子见 [README](../README.md)。

接待模型只提议意图和字段修改；程序校验输入，随后调用原 Agent。缺信息与待澄清问题不会立即执行业务。自然语言解释属于模型回答，结果状态、费用、截止时间、保存回执仍以结构化记录为准。Mock 对话只覆盖简单规则，不能作为通用聊天效果证据。

修改需求建立独立任务，原任务产物与费用保留，预算不跨任务共享。`/run` 完全相同输入回放最近任务；`/status` 与会话恢复不请求 API。会话 API 累计含对话和任务，任务用量单独保留。会话恢复不等于任务崩溃后自动续跑。

本次 82 项自动化测试通过，增加了分轮补信息、改预算、跨连接恢复、参数拒绝、结构化模型接待协议、可信状态隔离、费用保留、中断与可读输出测试。实际真实对话完成预算 10→6 的两次任务，总额依次为 8 和 3，原主题和截止时间保持一致，重复任务为零新增请求。原始输入、转录、Trace、用量和版本边界见 [交互验证记录](../examples/chat/README.md)。

真实测试发现完成自由说明中有一次月份复述错误。已避免在易读摘要中重复输出该自由复述，改为直接展示程序校验过的费用与时间。原 JSON 与转录保留，新增测试及零 API 恢复检查验证最终显示层。没有据此声明模型文字解释完全可信。

本次完整 API 验证基于已提交的本地冻结代码，其完整 Git tree 与公开 5c5cec6 相同；后续仅调整显示层并补测，没有重跑整批收费决策。详细 SHA、源码摘要和比较说明在记录中，不修改历史任务的执行版本来伪装成最新版本。

尚未实现 token 流式输出、多行编辑、通用代码工具、生产并发和崩溃任务续跑。个人实际阅读、修改、复测、题号和用时仍待用户本人补充。
